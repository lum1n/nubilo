# Nubilo for iPhone, iPad and Mac

One SwiftUI app target for iOS 17+ and macOS 14+ that replaces the CLI for
family members: join a server by scanning an invite, add Calendar, Contacts
and Reminders through a profile, back up the camera roll, browse and share
photos, and manage family members and devices. On the Mac it also runs the
home server from the menu bar.

```
apps/Nubilo
├── project.yml              XcodeGen spec (generates Nubilo.xcodeproj)
├── App/                     @main app, iOS app delegate, entitlements, asset catalog
├── Design/                  app icon sources (SVG); scripts/render-app-icon.sh renders them
├── Packages/NubiloKit/      API client, request signing, onboarding, photo backup engine
├── Packages/NubiloUI/       SwiftUI screens and the app model
└── Tests/Fixtures/          signing vectors generated by `go test ./internal/auth`
```

The HTTP contract is [docs/API.md](../../docs/API.md).

## Build

```sh
brew install xcodegen
cd apps/Nubilo
xcodegen                      # writes Nubilo.xcodeproj and App/Info.plist
open Nubilo.xcodeproj
```

XcodeGen 2.39 or later is needed (multi-destination target). Re-run
`xcodegen` after changing `project.yml` or adding files to `App/`; files in
the packages are picked up by Xcode directly.

**Signing.** Before the first `xcodegen` run, create an untracked
`project.local.yml` next to `project.yml` (xcodegen fails without it):

```yaml
settings:
  base:
    DEVELOPMENT_TEAM: ABCDE12345
```

then run `xcodegen`. Use `settings: {}` to pick the team in Xcode instead
(lost on the next `xcodegen`). Signing is automatic. The bundle id is
`dev.nubilo.app`; change `PRODUCT_BUNDLE_IDENTIFIER` in `project.yml` if that
id is not available to your team.

**The bundled server (macOS).** The Mac app runs the Go `nubilo` binary from
`Nubilo.app/Contents/Helpers/nubilo`. A post-build step copies it from
`bin/nubilo` at the repository root and signs it. Build it first:

```sh
scripts/build-wired.sh                 # with relay support (needs a wired checkout)
go build -o bin/nubilo ./cmd/nubilo    # without relay support
```

Set `NUBILO_CLI_SOURCE` to copy a binary from somewhere else. When the binary
is missing the build prints a warning and the menu bar server controls are
disabled. For a quick local run without rebuilding, launch the app with the
`NUBILO_CLI` environment variable pointing at a `nubilo` binary.

It sits in `Contents/Helpers` instead of `Contents/MacOS`: the app's own
executable is `Nubilo`, and the two names collide on case-insensitive APFS.

The macOS build has the App Sandbox off (see `App/Nubilo-macOS.entitlements`),
because the server it launches needs ports, `~/.nubilo` and LaunchAgents. It
is meant for Developer ID distribution, not the Mac App Store.

**Tests.** The `Nubilo` scheme's test action runs NubiloKit's XCTest target
(`⌘U`). The same tests run anywhere with Swift:

```sh
cd Packages/NubiloKit && swift test
```

They check the request signer byte for byte against vectors written by the Go
server (`go test ./internal/auth -update-vectors`). `LiveServerTests` runs
against a real server when `scripts/swift-live-test.sh` sets it up.

## Screens

**Onboarding.** Scan the invite QR code with the camera (VisionKit's data
scanner) or paste the link. Both `nubilo://setup?url=…&invite=…&fp=…` and
`https://<server>/join#<code>` work, and `nubilo://` links from Safari or
Messages open the app directly. The user picks a username and display name
and a device name; when the link names an existing account (`&user=`, from
Add a Device or `nubilo users invite --for`) only the device name is asked. The
app creates an Ed25519 key in the Keychain (this device only, readable after
first unlock), redeems the invite, signs the challenge, and checks the
server's key against the `fp` in the QR code. A LAN server's self-signed
certificate is pinned on first contact. Errors say what to do: username taken
(409), invite used or expired (401), server identity mismatch.

**Calendar & Contacts.** One button creates a single-use configuration
profile (CalDAV and CardDAV accounts with a fresh app password) and opens it
in Safari, the only place iOS installs profiles from. A numbered guide covers
Settings → Profile Downloaded → Install. Reminders ride on the CalDAV account.
On the Mac the profile opens in the browser and installs from System Settings.

**Files.** Shows the WebDAV address and username and creates a files-only app
password, shown once with a copy button. Finder connects with Go → Connect to
Server. The iOS Files app's Connect to Server only speaks SMB, so on iPhone
the guide points to a WebDAV-capable file app.

**Photos (iPhone and iPad).**
- *Backup*: asks for Photos access, then shows how many assets are backed up,
  waiting, uploading and failed, the last run and its errors. Settings: on/off,
  include videos, only while charging, use mobile data. Back Up Now runs a pass
  for up to ten minutes; uploads continue in a background URLSession after the
  app is closed, and iOS runs further passes as `BGProcessingTask`s.
- *Library*: a paged grid of the server library with thumbnails (memory cache
  plus a 500 MB URL cache) and a preview on tap. Select photos to add them to
  an album.
- *Albums*: own albums and albums shared with the user (owner and access
  shown), album grids, new albums, and sharing an album with family members as
  view-only or can-add.

On the Mac the backup screen is hidden: the Mac agent backs up Photos.app.

**Family.** Admins see all members with role, status, devices and storage;
can disable or enable a member and change roles; create invites shown as a QR
code with a share link, and revoke open ones; and see every device by owner
with revoke. Everyone sees their own devices (remove), app passwords (revoke)
and storage, and can add another device to their own account: My Devices →
Add a Device shows a QR code and a `nubilo://` link (single use, one hour) to
scan or AirDrop to the new iPhone or Mac.

**Settings.** Server address, account, and Sign Out, which revokes this
device on the server, deletes its key and forgets the server and the backup
state.

**Mac menu bar.** Server status from `nubilo server service`,
`nubilo --json status` and `nubilo doctor --json`, with failing checks and
their fixes; Start and Stop install and remove the server LaunchAgent
(`nubilo server install` / `uninstall`). Agent health comes from
`nubilo doctor --agent --json --data-dir ~/.nubilo-agent`; *Open Agent
Settings* runs `nubilo agent ui`, which opens the agent's selection page in
the browser. (The agent's loopback API needs the random session token that
`agent ui` prints on start, so the app does not call it directly.) *Set Up
Server* opens a wizard that runs `nubilo setup --json --step 1…5` with the
chosen mode (relay, direct or LAN), domain, email and relay invite, shows
each step's result, can continue from a failed step, and ends with the admin
invite QR code to scan with the iPhone.

## Limits

- **The app has not been compiled yet.** It was written in an environment
  without Xcode: NubiloKit builds and its tests pass on Linux, but the SwiftUI,
  UIKit, AppKit, PhotoKit, SwiftData and BackgroundTasks code was only
  syntax-checked. Expect the first Xcode build to need small fixes.
- **Photo backup is best effort.** iOS gives third-party apps no continuous
  background sync. Backup runs while the app is open, in `BGProcessingTask`
  windows iOS chooses (often at night on power), and as background uploads.
  Force-quitting the app stops all of it until the next launch.
- **Profiles are unsigned**, so iOS and macOS label them "Unverified". The
  profile link works once and expires after 15 minutes.
- **No way to ask the server whether an invite creates an account**, so the
  join form always asks for a username and the server ignores it for invites
  to existing accounts.
- The gallery lists the library oldest first, as the API pages it; videos
  show a still only.
- Moving `Nubilo.app` after starting the server breaks the LaunchAgent,
  which points into the app bundle. Stop and start the server again from the
  menu bar after moving it.
