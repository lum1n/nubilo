# Nubilo HTTP API (v2)

The contract the Nubilo apps build against. `GET /api/v1/status` returns `api_version` (currently `2`) and `features`. All bodies are JSON unless noted. Errors are plain-text bodies with the status code.

## Authentication

### Signed requests (paired devices)

Every request from a paired device carries

```
Authorization: Nubilo-Sig v1 device=<device_id>,ts=<unix_ms>,nonce=<16-128 chars>,sig=<base64 raw std>
```

`sig` is the Ed25519 signature, with the device key, of the canonical string (UTF-8, `\n`-separated, no trailing newline):

```
nubilo-sig/v1
<device_id>
<ts>
<nonce>
<METHOD uppercased>
<request URI: path plus "?query" exactly as sent>
<lowercase hex SHA-256 of the raw body; the empty body hashes to e3b0c442…b855>
```

`ts` must be within 60 s of server time, and a nonce is accepted once per device. `apps/Nubilo/Tests/Fixtures/signing_vectors.json` holds exact vectors generated by `go test ./internal/auth` (Ed25519 is deterministic); clients must reproduce them byte for byte.

### Upload tokens

`POST /api/v1/me/upload-token` → `{"token":"nbu_…","expires_at":<ms>}`, valid 24 h for **only** `PUT /sync/v1/blob/{hash}`, `POST /api/v1/photos/check` and `POST /api/v1/photos/commit`, sent as `Authorization: Bearer nbu_…`. Use them for background transfers that cannot be signed when the OS finally sends them.

### HTTP Basic (app passwords)

CalDAV, CardDAV, WebDAV and the photo endpoints accept `Basic <username>:<app password>`. The username is the user's username (or, for old accounts, the device id).

## Onboarding

QR codes and links carry either

- `nubilo://setup?url=<https base URL>&invite=<code>&fp=<server public key, base64url>[&user=<username>]` (from `nubilo setup`, `nubilo users invite`, the admin console, `POST /api/v1/me/device-invite`); `user` is present when the invite adds a device to that existing account, so the app asks only for a device name, or
- `https://<domain>/join#<code>` (shared links; the code is in the fragment).

Flow:

1. Generate an Ed25519 key pair on the device (keep the private key in the Keychain).
2. `POST /api/v1/invites/redeem` (no auth, 5/hour/IP)
   `{"code","username","display_name","device_name","public_key":"<base64 32 bytes>"}` → `{"pairing_id","challenge":"<base64>","server_id":"<base64 server key>","user":{…}}`.
   `username` is required when the invite creates a new user (409 if taken, 400 if invalid: 1–32 of `a-z0-9._-`); invites for an existing user ignore it.
3. Sign the raw challenge bytes with the device key and `POST /api/v1/pair/complete {"pairing_id","signature":"<base64>"}` → `{"device_id","user_id","created_at","server_public_key"}`.
4. Pin `server_public_key` (it must equal `fp` from the QR when present). Self-signed LAN servers: pin the TLS certificate on first contact.

The older code flow (`POST /api/v1/pair/begin {code,name,public_key}` then `pair/complete`) still works for `nubilo pair`.

## Me

| Request | Response |
| --- | --- |
| `GET /api/v1/me` | `{"user":{id,username,display_name,role,status,created_at},"device":{id,name,role,user_id,…},"storage":{"objects","bytes"},"urls":{"caldav","carddav","webdav","photos"}}` |
| `GET /api/v1/me/passwords` | `{"passwords":[{"id","label","scope","created_at","last_used"}]}` |
| `POST /api/v1/me/passwords {"label","scope"}` | 201 `{"id","username","password"}` — the password is shown once; scope is a comma list of `caldav,carddav,webdav,photos` or `all`; at most 10 per user (409) |
| `DELETE /api/v1/me/passwords/{id}` | `{"revoked":id}` |
| `POST /api/v1/me/profile {"services":["caldav","carddav"]}` | 201 `{"url","expires_at","password_id"}` — open `url` in Safari within 15 minutes; it downloads once |
| `POST /api/v1/me/device-invite` | 201 `{"id","code","url","setup_url","expires_at","role","max_uses"}` — adds a device to the caller's own account: single use, expires in 1 hour; the redeemer's username is ignored. App-password (dav) devices get 403 |
| `GET /api/v1/profile/{token}` | `application/x-apple-aspen-config` (no auth; single use) |
| `GET /api/v1/devices` | own devices `[{"id","name","role","user_id","created_at","last_seen","revoked"}]`; admins add `?all=1` |
| `POST /api/v1/devices/{id}/revoke`, `/rename {"name"}` | own devices (admins: any) |
| `GET /api/v1/users` | `{"users":[{"id","username","display_name"}]}` active users, for share pickers |

## Collections and sharing

| Request | Response |
| --- | --- |
| `GET /api/v1/collections` | `{"collections":[{…collection, "owner","owner_user_id","root_id","access":"owner"\|"rw"\|"ro","shares":[…] (owners, roots only)}]}` |
| `GET /api/v1/collections/{id}/shares` | `{"shares":[{"collection_id","principal_type":"user","principal_id","username","access","created_by","created_at"}]}` (owner only) |
| `PUT /api/v1/collections/{id}/shares {"username"\|"principal_id","access":"ro"\|"rw"}` | the updated list |
| `DELETE /api/v1/collections/{id}/shares?username=…` | the updated list |

Only top-level collections can be shared; everything below inherits the share.

## Photos

| Request | Response |
| --- | --- |
| `GET /api/v1/photos?after=<id>&limit=<≤1000>` | `{"photos":[photo],"next":"<id or empty>"}` the caller's library, oldest first |
| `GET /api/v1/photos/{id}` | photo metadata (`id, name, mime, width, height, taken_at_ms, kind, checksum, thumb_hash, preview_hash, live_pair_hash, collection_id, …`) |
| `GET /api/v1/photos/{id}/thumb` \| `/preview` \| `/original` | image bytes (Range supported); also for album items |
| `POST /api/v1/photos?name=…` (body = file) | 201 photo |
| `POST /api/v1/photos/check {"hashes":[sha256…]}` | `{"missing":[…]}` hashes not yet in the library (≤1000 per call) |
| `PUT /sync/v1/blob/{sha256}` (body = file) | `{"blob_id","size"}` |
| `POST /api/v1/photos/commit {"blob_id","name","taken_at","local_id","live_video_blob"}` | 201 photo; derivatives are made on the server; idempotent per content |
| `GET /api/v1/albums` | `{"albums":[{"id","name","owner","access","created_at","updated_at"}]}` own and shared |
| `POST /api/v1/albums {"name"}` | 201 album |
| `GET /api/v1/albums/{id}/items?after=&limit=` | `{"items":[photo + "photo_id"],"next"}` |
| `POST /api/v1/albums/{id}/items {"photo_ids":[…]}` | `{"items":[…]}` |

Share an album with `PUT /api/v1/collections/{album id}/shares`.

Backup loop for a phone: hash each asset → `photos/check` in batches → for each missing hash `PUT /sync/v1/blob/{hash}` (background upload with an upload token) → `photos/commit`.

## Sync (`/sync/v1`, signed)

Unchanged from SYNC.md, with per-user scoping: `hello` returns `collections_rev`, which changes whenever the caller's visible collections (or their access) change; skip `POST /sync/v1/collections` while it is unchanged. `changes` only contains entries of collections the caller can read. Collections carry `owner_user_id`, `owner`, `root_id` and `access`.

## DAV

| URL | |
| --- | --- |
| `/.well-known/caldav`, `/.well-known/carddav` | redirect (after auth) to the user's principal |
| `/caldav/u/<username>/calendars/<id>/<uid>.ics` | own calendars and calendars shared with the user (shown as "Name (owner)"); read-only shares advertise only `DAV:read` |
| `/carddav/u/<username>/addressbooks/<id>/<uid>.vcf` | same for address books |
| `/dav/files/<name>/…` | own file roots |
| `/dav/shared/<owner>/<name>/…` | file roots shared with the user |

Accounts created before multi-user support keep using `/caldav/user/calendars/<name>/`.
